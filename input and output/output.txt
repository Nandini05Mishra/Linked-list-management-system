=========== SINGLY vs DOUBLY LINKED LIST ===========

Feature                    Singly                 Doubly                
--------------------------------------------------------------------
Pointers per node          1 (next)               2 (prev, next)        
Extra memory per node      less                   more (one extra ref)  
Traversal                  forward only           forward + backward    
Insert at beginning        O(1)                   O(1)                  
Insert at end              O(n) (no tail)         O(1) (with tail)      
Delete from beginning      O(1)                   O(1)                  
Delete from end            O(n)                   O(1) (with tail)      
Delete a known node        O(n) need previous     O(1) has prev link    
Search / Count / Min/Max   O(n)                   O(n)                  
Reverse                    O(n), 3 pointers       O(n), swap prev/next  
Link bugs to watch for     next only              prev AND next, tail   

Measured on this machine (N = 20000 operations, sort size = 3000):
--------------------------------------------------------------------
Operation                           Singly (ms)  Doubly (ms)
Insert at beginning x N                   5.338        1.874
Insert at end x N                       338.229        4.979
Search (not found) x 500                 23.562       25.865
Reverse once                              0.311        0.361
Delete from end x N                     335.326        2.719
Bubble Sort                              25.175       21.162
Merge Sort                                3.430        3.829

Takeaway: the doubly list costs more memory and more pointer updates,
but gives O(1) end operations, backward traversal and O(1) deletion of a known node.
(Timings vary between runs/machines; the growth pattern is what matters.)
